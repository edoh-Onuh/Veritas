# Scripts

## submit_claim.py

Bridges the off-chain engine to the on-chain program. Scores a claim, then
prints the exact `submit_claim` instruction arguments (inputs_hash, integrity
score in basis points, claimed CO2, bond).

```bash
python scripts/submit_claim.py --demo good       --dry-run
python scripts/submit_claim.py --demo impossible --dry-run
python scripts/submit_claim.py --demo inflated   --dry-run
python scripts/submit_claim.py --energy 1400 --claimed-co2 250 --capacity 5000
```

## submit_onchain.js

Sends what the bridge scored. The bridge stays the deterministic scorer and this
stays the signer, so the engine never needs a funded keypair and this never
needs to know any physics.

```bash
yarn install                 # the client needs @coral-xyz/anchor resolvable
python scripts/submit_claim.py --demo good --json > /tmp/claim.json

export ANCHOR_PROVIDER_URL=https://api.devnet.solana.com
export ANCHOR_WALLET=~/.config/solana/id.json
# running it from outside the repo? point Node at the repo's modules:
#   export NODE_PATH=/path/to/veritas/node_modules

node scripts/submit_onchain.js submit    /tmp/claim.json
node scripts/submit_onchain.js show      /tmp/claim.json
node scripts/submit_onchain.js challenge /tmp/claim.json [stakeLamports]
node scripts/submit_onchain.js resolve   /tmp/claim.json <scoreBps>
```

It reads the IDL from `target/idl/veritas.json` (override with `VERITAS_IDL`),
derives every PDA from the claim's own figures, and prints an explorer link for
each transaction. Two rules the program will enforce: the wallet must be the
asset's **registered owner** to submit, and a **committee member** to resolve. A
claim the engine refused to score has no `inputs_hash`, and the client stops
rather than inventing one.

For a typed client inside a wallet app, use the pattern in
`app/src/veritas.test.ts`, which has the `@coral-xyz/anchor` types generated by
`anchor build`.
